# 代码库审查 Agent 设计（code-reviewer）

Date: 2026-09-16
Status: Approved
Project: agent-service-toolkit（面试展示）

## Goal

新增一个服务内 agent：面向 git 仓库的**变更审查 + 代码问答**工具，替换项目里
缺乏真实性的玩具 demo，用真实 git 历史做数据源，构成面试主叙事。

## 范围与排除

- 两个技能：变更审查（主叙事）+ 代码问答（工具多样性）。
- 严格只读工具集：agent 只能读和分析，零写操作，与「不提交代码」要求天然一致。
- 排除：技术债扫描、issue 生成、自动写报告文件、代码向量检索（RAG）。

### 为什么要排除 RAG（可行性核查结论）

`src/agents/tools.py:55` 的 `OpenAIEmbeddings()` 要求 OPENAI_API_KEY 且
`./chroma_db` 已存在；当前环境两者皆无（`OPENAI_API_KEY not set`，`chroma_db`
不存在），RAG 工具一调用即崩。v1 用纯 git + 文件工具，grep/read 的可解释性
本身就比 embedding 黑箱更能扛面试追问；RAG 留待有 key 再议。

## 1. 架构

注册进 `agents.py` dict（key: `code-reviewer`），复用 FastAPI `/stream` +
Streamlit UI + checkpointer/store 全套基础设施，与现有 agent 同构。

```
guard_input(可选项，无 GROQ 时自动跳过) → model → 条件边 ──→ tools(ToolNode)
                                              │                 │
                                              └── 无工具调用      │
                                                   → END  ←──────┘
```

图模式完全复用 `loop_agent.py`：`StateGraph + MessagesState + RemainingSteps
+ ToolNode + pending_tool_calls`，零新基建。

### 1.1 工具集（全部只读）

| 工具 | 作用 | 实现 | repo_path |
|---|---|---|---|
| `git_log` | 读提交历史（含 diff stat） | subprocess 调 `git log` | 可选 |
| `git_diff` / `git_show` | 读特定提交的完整 diff | subprocess | 可选 |
| `file_search` | grep 定位代码（文件名/内容） | Python 标准库 glob + 正则 | 可选 |
| `read_file` | 读文件内容（截断防溢出） | Path.read_text | 可选 |

- 所有工具签名带 `repo_path` 参数，默认指向 service 工作目录（本项目根目录）。
- git 子进程安全要求：
  - 固定参数 `--no-pager`、显式 `--format`/`--stat`，不给 shell 拼接机会
  - 禁用一切写操作（reset / checkout / commit / push）
  - `text=True, capture_output=True`，设置超时
- `file_search` 以 `--search-path` 白名单目录为根，用 `pathlib.rglob`，不做
  embed 索引，结果可解释。

### 1.2 长期记忆（store）

变更审查完成后，把结论写入 store（interrupt_agent 已验证同款机制）：
- namespace：`("code-reviewer", user_id, repo_name)`
- key：文件或模块名（如 `"loop_agent.py"`）
- value：`{"conclusion": str, "analyzed_at": iso, "commit": str}`
- 后续问答先 `store.aget`，命中则免跑 git 直接引用；`aput` 前先查重。

写入点在 `model` 节点之后，通过 `store: BaseStore` 参数注入（同
`interrupt_agent.py:78`）。

## 2. 交互契约

- `/code-reviewer/stream`：流式消息 + 工具调用过程（Streamlit 默认 stream）。
- 审查指令示例：「review 最近 5 次提交，输出每个变更的文件、风险点、建议」。
- 回答必须引用真实 git 输出，不编造。

## 3. 测试

- `tests/agents/test_code_reviewer.py`：
  - 编译断言：节点 `{"model", "tools"}` 存在、`pending_tool_calls` 分支健全
  - 工具单测：用 `tmp_path` 构造微型 git 仓库（`git init` + 两次提交），断言
    `git_log`/`git_diff` 返回该仓库真实输出；`read_file` 截断行为
  - store 集成：fake model 跑一轮，断言结论写入 store（用内存 store）
- CI 无 git 上下文的测试全部走 `tmp_path` 自建仓库，不依赖 CI 的 git 状态。

## 4. 风险与对策

- **/invoke 吞中间消息**（`service.py:213` 限制）：引导用户走 `/stream`；
  Streamlit 侧已默认 stream，零额外成本。
- **子进程超时**：git 大仓库 diff 可能慢，设 `timeout=30s`，超时返回可读错误。
- **README 中文化**：`streamlit_app.py` 已有中文 UI，新 agent 欢迎语按同风格。
