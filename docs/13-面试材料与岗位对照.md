## 简历条目

### 2026.05 -- 至今　　　企业研发效能多智能体平台（DevFlow Agents）　　　开发人员

本项目基于 LangGraph、FastAPI、LangChain、Streamlit，自研设计出的一款面向研发团队的 Agent 服务中台，提供统一的智能体接入、编排、对话与记忆能力。

**项目功能：** 平台内置 12 个职能各异的智能体，覆盖代码库审查、GitHub 仓库操作（MCP）、RAG 知识问答、技术研究助手（联网搜索+计算）、主管编排、人工审批与后台任务调度等研发场景；统一基于 FastAPI 的 SSE 流式接口与 AG-UI 协议对外提供服务，内置内容安全过滤（safeguard）与 AUTH_SECRET 鉴权，支持多轮对话持久化、跨会话长期记忆、工具调用与人工介入，支持 DeepSeek / OpenAI / Anthropic / Gemini / 本地模型多供应商切换。

**项目成果：**
1、基于 LangGraph 状态图落地多智能体编排，实现单智能体、ReAct 循环、主管调度、嵌套层级主管等模式，以 interrupt 机制完成敏感操作的人工审批（HITL）闭环；
2、基于 langchain-mcp-adapters 构建 GitHub MCP 客户端动态加载远端工具，封装联网搜索、命令行执行、代码库只读审查等真实工具，以路径穿越防护、固定 git 参数防注入、30s 超时与最大步骤数兜底，防范死循环与成本失控；
3、checkpointer 持久化会话状态、Store 存储跨会话长程记忆，支持 SQLite / Postgres / MongoDB / Redis 一键切换，任意请求可续上下文，中断-恢复状态一致；
4、对 50/200/1000 并发做分层压测，量化服务层与 LLM 供应商延迟占比，定位多 worker 下 SQLite checkpoint 文件锁竞争导致的 P95 击穿（44.9s），据此设计并验证 Redis 共享存储迁移方案；
5、对接 LangSmith / Langfuse 追踪 Agent 决策链路与工具调用轨迹，接入 pytest（271 单测全绿，另有 7 个联网用例默认跳过，含联网 278 通过）、ruff、GitHub Actions CI 与 pre-commit，形成工程质量闭环。

### 可以在面试里讲的「真问题」

这两处是真实环境下发现、定位并修掉的缺陷，比功能罗列更有说服力：

1. **两个 supervisor agent 的转交必 500** —— DeepSeek thinking 模式要求历史里每个
   content-only assistant 消息回传 `reasoning_content`，而 `langgraph_supervisor`
   恰恰把子 Agent 的终答拼成这样一条消息，`ChatOpenAI` 又从不捕获该字段；
   `output_mode` / `add_handoff_back_messages` 两种调参都无效（已实测否证）。
2. **code-reviewer 的 git 工具在本机必崩** —— `subprocess.run(text=True)` 未指定
   `encoding`，服务进程按 cp936 解码 UTF-8 的 git 输出，reader 线程抛
   `UnicodeDecodeError` 后 `stdout` 变 `None`，`.strip()` 直接 500。
   测试拦不住是因为**测试环境 ≠ 运行环境**（测试提交信息全 ASCII + 继承 `PYTHONUTF8=1`）。

两者的成因、否证过程与修法已记入 `docs/11-Agent能力完善方案.md`
与 `docs/10-审核与修复总账.md`。
