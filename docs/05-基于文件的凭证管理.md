# 基于文件的凭证管理

开发 agent 的过程中，你可能会发现有些凭证需要存放在磁盘上，但你不希望它们进入 Git 仓库，也不想被打包进容器镜像。

例如：

- 基于文件的 LLM 凭证文件（如 Google Vertex）
- 与外部 API 通信所需的证书或私钥

`privatecredentials/` 目录为开发阶段提供了存放这些文件的便捷位置。

## 工作机制

### 保护措施

- `.dockerignore` 排除了整个目录，使其不参与构建过程。
- `.gitignore` 只放行 `.gitkeep` 文件——因为 git 不跟踪空目录。

### 挂载卷

docker compose 文件把 `privatecredentials/` 挂载进容器，路径为 `/privatecredentials/`。运行中的容器因此可以访问你开发环境里那些未被 git 跟踪的文件。

### 为什么不用 Docker Watch

这里没有使用 Docker Watch 的同步功能，原因如下：

- docker watch 遵守 `.dockerignore` 的规则，因此根本看不到这些凭证
- 即使能看到，docker watch 也不会在容器启动时做一次初始同步，只会同步服务运行期间发生的变更

## 建议用法

对每一个基于文件的凭证，按以下步骤操作：

1. 把文件（例如 `example-creds.txt`）放进 `privatecredentials/` 目录
2. 在 `.env` 文件中为该凭证创建一个环境变量（例如 `EXAMPLE_CREDENTIAL=/privatecredentials/example-creds.txt`），供 agent 在运行时引用该路径
3. 在 agent 中，凡是需要凭证路径的地方都使用这个环境变量

### 示例

#### Google Vertex

Google Vertex SDK 通过 `GOOGLE_APPLICATION_CREDENTIALS` 环境变量定位你的凭证文件。

操作步骤：

1. 把 `service-account-key.json`（或 `google-credentials.json`）放进 `privatecredentials/` 目录
2. 在 `.env` 文件中定义 `GOOGLE_APPLICATION_CREDENTIALS=/privatecredentials/service-account-key.json`
3. Vertex SDK 会自动读取 `GOOGLE_APPLICATION_CREDENTIALS` 环境变量。

#### 与远程 API 安全通信所需的证书

如果你的 agent 调用的远程 API 需要客户端证书，那么 agent 需要能访问该公开证书。

例如，假设你有一个名为 `my_remote_api_certificate.cer` 的证书。

操作步骤：

1. 把 `my_remote_api_certificate.cer` 放进 `privatecredentials/` 目录
2. 在 `.env` 文件中定义 `MY_REMOTE_API_CERTIFICATE=/privatecredentials/my_remote_api_certificate.cer`
3. 让 agent 中的 HTTP 客户端通过该环境变量的值访问该文件

## 生产环境方案

在生产环境中，你需要让基于文件的凭证对应用可用，并通过环境变量指定容器访问它们的路径。

有若干种方案：

- 使用 Kubernetes Secrets 或 Docker Secrets，以数据卷方式挂载，让应用以文件形式访问
- 使用云主机厂商的密钥管理功能（Google Cloud Secrets、AWS Secrets Manager 等）
- 使用第三方密钥管理平台
- 手动把凭证放到 Docker 宿主机上，再通过挂载卷映射进容器（安全性较低）
